# Firmware 12.70 port notes

The default `byepervisor_reborn.elf` now dispatches firmware 12.70 to its
dedicated resume path. The 12.70 hook is compiled with its own arm and
continuation chain while the existing hook remains available for other
firmwares. The shared paging and copy helpers also gain checks needed by
the 12.70 path. It is restricted to the launch model
(`sceKernelGetMainSocId() == 0x840f60`).

## Resume path

The payload checks the 12.70 kernel offsets, the fixed physical carrier at
`0x3ffff000`, the empty data cave, and the guest mappings before arming a
one-shot `#DB` hook on `hv_mp_startup_call`. The 224-byte AP stub runs during
S3 resume. It checks all 16 AP VMCBs, clears the nested-paging enable bit
in each control word and its related field at offset `0xc0`, then reports
its result through a kernel data-cave marker. The process waits
for resume, checks the marker and cleanup result, then reads the first eight
bytes of kernel text as proof that XOTEXT was cleared.

Before arming the hook, `textmap_1270.c` walks the entire `0xd50000`-byte
kernel text range. It accepts the two page layouts observed on the test
console: five or six 2 MiB leaves, with the rest mapped as 4 KiB pages.
Every targeted leaf must start as present, executable, XOTEXT, and read-only.
The code records unique leaf addresses, checks coverage and readback, then
clears XOTEXT and sets RW. It restores the original entries if preparation
fails. A successful resume leaves the changes active until reboot.

## Multicore debug-hook hardening

The 12.70 path now checks all 16 TSS records before installing the shared
vector-1 gate. It requires distinct RSP0 and IST4 values, an unused IST6 slot
on every CPU, and the expected stock IST4 gate. Each non-selected CPU gets
its own 0x100-byte IST6 fallback stack at `cave+0x2000` through `cave+0x2eff`.
The selected CPU keeps its original arm and handler chain. Every fallback
image and IST6 pointer is read back before the replacement gate is published.
The replacement changes only the gate's low qword; its high qword must match
the stock value. The selected handler restores the stock gate and clears DR7
before staging the AP code. Cleanup verifies the stock gate first, then each
CPU's original IST6 value, and finally the saved fallback-cave bytes.

This adaptation follows the per-CPU design validated for 11.60 in
[PS5Dev/Byepervisor-Reborn issue #9](https://github.com/PS5Dev/Byepervisor-Reborn/issues/9).
Build `census_1270.elf` with `make census_1270.elf` to check the gate, all
16 TSS records, and the fallback-cave range without kernel writes. Its
`CENSUS1270,result` line must report `bad=0` and
`occupied_fallback_bytes=0` before trying the modified strike.
The new 12.70 hook has passed a host test covering installation order,
foreign CPU stacks, refusal on an occupied IST6 slot, partial install
rollback, and zero-valued IST6 readback failures. It has **not** yet been
tested on a 12.70 console. The known-good single-core ELF remains the live
reference until a read-only 12.70 TSS census and a controlled strike pass.

## Evidence and limits

On one launch-model 12.70 PS5, the standalone 12.70 ELF completed a clean
rest/resume cycle. The USB result recorded:

```
textmap,planned,count=342
textmap,verified,count=342
result,bp=0x1270dbdb5eedbeef,ap=0x1270a9e17e5e2002,survey_count=16,...cleanup=0
end,vmcbs=16,text_entries=342,text_verified=342,text_read=0,first8=0x0000000058c55be8
```

USB logging is optional. If `/mnt/usb0` is unavailable, the payload still
arms the hook, checks the resume markers, and reports the final text bytes in
a notification. It also writes the result line to klog.

The combined ELF builds but has not yet been run on a console. The full
kernel text range was also dumped in a separate test on this console.
The 12.70 path itself only reads and displays eight bytes;
it does not include a dump, Linux loader, or persistent patch set. The
12.70 offset table includes inherited candidate entries that this path
does not exercise; those entries should not be taken as proof that the
generic firmware path works on 12.70. The result is limited to
the tested model and firmware, and additional hardware runs are needed
before wider support can be claimed.
